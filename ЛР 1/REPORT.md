### Цель
Создать устанавливаемый пакет для приёма сдач онлайн-школы, их валидации и запуска заменяемых анализаторов без исполнения студенческого кода.

### Этап А
Модель `Submission` создана как `@dataclass(frozen=True, slots=True)`. Валидатор выполняет runtime-проверки типов и обязательных полей, версии схемы, часового пояса, непустых ID и декларации ИИ. Входной объект не изменяется. SHA-256 вычисляется по каноническому JSON с фиксированным порядком ключей. Сервис различает `accepted`, `duplicate` и `conflict`. Повреждённая строка JSONL не прерывает обработку файла.

### Этап Б
Интерфейсы `SubmissionRepository`, `SubmissionSource`, `Analyzer` определены через `Protocol`. `LengthAnalyzer` подсчитывает непустые строки, а `TemplateAnalyzer` ищет точные совпадения с разрешённым шаблоном. Оба возвращают `AnalysisReport` с метаданными анализатора и номерами строк. `AnalysisService` вызывает анализатор через `AnalyzerRegistry` и проверяет отчёт, включая границы evidence. Источники `JSONLSource` и `InMemorySource` имеют одинаковый контракт. Файловый источник владеет ресурсом и закрывает его при выходе из `with`.

### Расширяемость
В примере дополнительно подключается `DeclarationAnalyzer` через `registry.register("declaration", DeclarationAnalyzer)`. Изменения центрального сервиса не требуются. Это демонстрация расширения для защиты, без внешних пакетов и дополнительного уровня сложности.

### Углубление и его эффект
Реализован типизированный декоратор `timed` (`ParamSpec`, `TypeVar`, `wraps`) для измерения времени выполнения без изменения сигнатуры и результата вызываемой функции. Замер производится в `finally`, поэтому фиксируется и при исключении. Эффект: единый механизм диагностики можно применять к разным функциям без копирования измерительного кода. В тестах проверены сохранение метаданных и корректность при ошибке.

### Проверки и воспроизведение
Из корня проекта:

```bash
python -m pip install -e ".[test]"
python -m pytest -q
school-lab import data/submissions.jsonl
school-lab import data/invalid_submissions.jsonl
school-lab analyze data/submissions.jsonl --analyzer template
```

Тестами проверяются: валидный импорт, неверные поля и типы, повреждённый JSON, дубликат, конфликт, неизменность входа, ошибка анализатора, контракты двух источников и анализаторов, точность evidence, закрытие файла после раннего выхода или исключения.

### Объяснение решений
Аннотации типов не проверяют входной JSON во время работы программы: эту задачу решает parser. `Protocol` описывает структуру поведения без обязательного наследования. Доменные исключения не зависят от HTTP; CLI отображает `code`, `field`, `message`. `with` управляет файловым дескриптором. Хеш защищает от незаметной перезаписи одной версии сдачи. Совпадение с шаблоном разрешено и не является оценкой плагиата.

### Ограничения
Хранение только в оперативной памяти; поиск только точных совпадений; нет сети и исполнения кода студентов; отчёты не сохраняются в постоянное хранилище. Внешние entry points не реализованы: в соответствии с требованием выбрано другое углубление Python Core — декоратор времени.
